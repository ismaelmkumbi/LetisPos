Subsystem 2: QR Codes on Documents

Embedded as SVG in Handlebars templates — zero frontend changes needed

How it works
1. Backend: Add QRCodeGenerator.java using the ZXing ("Zebra Crossing") library. Method: generateSvg(String data, int size) → String (inline SVG, no external image)

2. Template context: DocumentService.generate() auto-injects {{qrCode}} as an SVG data string into the template context. Template authors just add {{{qrCode}}} (triple-stash for raw HTML).

3. Use cases:
  • Invoice verification — QR encodes URL: https://letispos.com/verify/INV-00042
  • Payment link — QR encodes payment URL: https://pay.letispos.com/INV-00042
  • TRA e-invoice — QR encodes receipt verification code
  • Tracking — QR encodes delivery tracking URL
Template integration
Each template can include QR placement like: 
<div class="qr-code">
  <div>Scan to verify</div>
  {{{qrCode}}}
  <div>{{document.number}}</div>
</div>
The {{{qrCode}}} placeholder renders as a clean inline SVG. Triple-stash prevents HTML escaping.
What it takes
Dependencies: Add com.google.zxing:core and com.google.zxing:javase to document-service pom.xml
New files: 1 Java class (QRCodeGenerator), 1 Handlebars helper registration
Template changes: Add QR code section to invoices and receipts (optional per template)
Total effort: ~1 day
