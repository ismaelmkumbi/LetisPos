Subsystem 4: Document Version History

Track every generated document revision with full audit trail

Data Model
ColumnTypePurpose
idUUIDPK
document_idUUID FKLinks to documents table
version_numberINT1, 2, 3... per document
storage_pathVARCHARMinIO key for this version's PDF
change_typeVARCHARcreated, reprinted, status_change, regenerated
change_summaryVARCHARHuman-readable: "Status changed from draft to sent"
created_byUUIDWho triggered this version
created_atTIMESTAMPWhen
When versions are created
1. First generation — v1 created with change_type = "created"
2. Regeneration — User clicks Generate again on same transaction → v2 with "regenerated"
3. Status change — Document marked as sent/paid/cancelled → new version with "status_change"
4. Reprint — User clicks Print/PDF → new version with "reprinted"
5. Email/WhatsApp — Each send creates a version with "sent_email" / "sent_whatsapp"
Frontend: Version Timeline
A new DocumentVersionTimeline.tsx component added to DocumentPreviewModal as a third tab. Shows vertical timeline of all versions with date, user, change type, and a "View PDF" button for each.
What it takes
New DB table: document_versions (Flyway V2 migration)
New entity + repository: DocumentVersion.java + DocumentVersionRepository.java
Modified: DocumentService.generate() auto-creates v1, regenerate/reprint creates new version
New endpoint: GET /api/v1/documents/{id}/versions
New component: DocumentVersionTimeline.tsx
Total effort: ~2 days
