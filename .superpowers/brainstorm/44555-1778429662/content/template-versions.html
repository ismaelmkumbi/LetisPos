Subsystem 5: Template Versioning & Rollback

Git-like history for template edits — see what changed, roll back to any version

Data Model
ColumnTypePurpose
idUUIDPK
template_override_idUUID FKLinks to template_overrides
version_numberINTSequential per override
body_htmlTEXTFull template content at this version
change_descriptionVARCHAR"Added QR code section", "Changed font size"
updated_byUUIDWho made this edit
updated_atTIMESTAMPWhen
How it works
1. On save: When template override is updated via PUT /templates/{type}, the current body_html is archived to template_versions before the update is applied. Version number auto-increments.

2. Rollback: POST /api/v1/templates/{type}/rollback with {"version": 3} restores version 3's body_html as the active override. This itself creates a new version (e.g., v4 = "Rolled back to v3").

3. Diff view: Frontend shows side-by-side or unified diff between any two versions. Simple text diff using a lightweight JS library.

4. Version list: Timeline component in template editor showing all versions with who, when, and what changed.
What it takes
New DB table: template_versions (Flyway V3 migration)
New entity + repository: TemplateVersion.java
Modified: TemplateService.saveOverride() to archive before save
New endpoints: GET /templates/{type}/versions, POST /templates/{type}/rollback
New frontend: TemplateVersionTimeline.tsx, VersionDiff.tsx
Total effort: ~2 days
