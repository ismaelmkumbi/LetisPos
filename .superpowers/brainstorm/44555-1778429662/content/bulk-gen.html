Subsystem 6: Bulk Document Generation

Generate PDFs for multiple records at once with async progress tracking

How it works
1. User selects records — checkboxes on list pages (SalesListPage, PurchasesListPage, CustomersListPage, etc.)

2. Clicks "Bulk Generate" — selects document type, triggers async job

3. Backend processes — for each record: generate PDF, store in MinIO, create document record. Reports progress (X of Y complete).

4. User downloads — individual PDFs or a single ZIP via MinIO presigned URLs. Progress shown in a toast notification.
API Design
MethodPathPurpose
POST/api/v1/documents/bulkSubmit bulk job: {documentType, referenceIds: [...]}
GET/api/v1/documents/bulk/{jobId}Poll status: {status, progress, total, results: [...]}
GET/api/v1/documents/bulk/{jobId}/downloadDownload ZIP of all generated PDFs
Architecture
Async processing: Spring @Async with TaskExecutor — same pattern as report-service's ExportJobService
Job storage: bulk_jobs table (job_id, tenant_id, status, progress, total, results_json, created_at)
Progress tracking: Atomic counter updated after each document is generated
ZIP creation: Download endpoint streams a ZIP of all PDFs from MinIO using ZipOutputStream
Frontend: BulkGenerateDialog.tsx — select document type, confirm, watch progress bar, download
What it takes
New DB table: bulk_jobs (Flyway V4 migration)
New entity + repo: BulkJob.java
New service: BulkGenerationService.java (@Async processing)
New controller endpoints: 3 endpoints in DocumentController
New frontend: BulkGenerateDialog.tsx, BulkProgressToast.tsx
Modified: List pages add checkbox selection + Bulk Generate button
Total effort: ~3 days
