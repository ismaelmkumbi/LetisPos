Design — Section 4: Frontend Pages

Each page reuses existing shared components: PageHeader, DataTable, FilterBar, BulkActionBar

1. SuspendedSalesPage

Route: /smartpos/sales/suspended — lists all open suspended carts across terminals.

Page layout
PageHeader — title: "Suspended Sales", subtitle: "Carts on hold from POS terminals", badge: count of open
FilterBar — search by ref/terminal/customer, date range, status filter (OPEN / EXPIRED)
BulkActionBar — "Discard selected" for bulk delete of expired/abandoned holds
DataTable columns: #, Ref, Terminal, Cashier, Customer, Items (count), Total, Created, Expires, Actions
Row actions: Resume (navigates to POS with cart loaded), View details, Discard
Row click: opens detail drawer showing full cart contents

Resume flow: click Resume → POST /{id}/resume → receive cart payload → localStorage.setItem('pos.resumeCart', JSON) → navigate to /smartpos/sales/pos → POS reads resumeCart on mount

2. GoodsReceivedPage

Route: /smartpos/purchases/received — track what's been received against POs.

Page layout
PageHeader — title: "Goods Received", subtitle: "Track received inventory against purchase orders"
FilterBar — search by PO ref/supplier, supplier dropdown, date range, status (ORDERED / PARTIAL / RECEIVED)
DataTable columns: #, PO Ref, Supplier, Date, Ordered Qty, Received Qty, Remaining, Status
Row actions: Receive items (opens receive modal), View PO
Row click: navigates to purchase builder for full detail

Receive modal: shows each line with ordered qty, already received qty, input for qty receiving now. POST /purchases/{id}/receive-line on submit.

3. SupplierReturnsPage

Route: /smartpos/purchases/returns — dedicated list for purchase returns.

Page layout
PageHeader — title: "Supplier Returns", subtitle: "Goods returned to suppliers", badge: pending count
FilterBar — search by ref/supplier, supplier dropdown, status (PENDING / COMPLETED / CANCELLED), date range
DataTable columns: #, Ref, Supplier, Original PO, Lines, Total, Status, Date, Actions
Row actions: Complete (status → COMPLETED), Cancel, View PO, Credit Note (DocumentActionsBar)
Row click: navigates to purchase builder for context

4. SupplierPaymentsPage

Route: /smartpos/supplier-payments — supplier payment ledger.

Page layout
PageHeader — title: "Supplier Payments", subtitle: "Track all payments made to suppliers", metrics: total paid this month
FilterBar — search by ref/supplier, supplier dropdown, payment method, date range, account filter
DataTable columns: #, Supplier, Purchase Ref, Amount, Method, Account, Date, Reference
Row click: navigates to the purchase the payment was made against
Ledger view: clicking a supplier row opens a drawer showing: purchases (debits), payments (credits), running balance

All 4 pages follow the exact same component patterns as the existing Sales, Returns, and Quotations pages. Does the UX flow for each page look right?
