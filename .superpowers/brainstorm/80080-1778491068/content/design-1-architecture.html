Design — Section 1: Architecture

Where each feature lives and how components connect

Backend (sales-service)

All 4 features live in backend/sales-service, following the existing DDD-lite layering: Controller → Service → Repository → Entity.

Suspended Sales — NEW
api/SuspendedSaleController.java
application/SuspendedSaleService.java
domain/model/SuspendedSale.java
domain/repository/SuspendedSaleRepository.java
api/dto/SuspendedSaleDto.java

Entity fields: id, tenantId, terminalId, userId, lines (JSON), customerId, warehouseId, discountType, discountValue, taxMethod, notes, createdAt, expiresAt
Goods Received — EXTEND Purchase
Existing: PurchaseController, PurchaseService, Purchase entity

Add receiving-focused endpoints:
GET /purchases/receiving — list received items
POST /purchases/{id}/receive-line — partial receive

Add to PurchaseLine: receivedQty, receivedAt
Supplier Returns — EXTEND PurchaseReturn
Existing: PurchaseReturnController, PurchaseReturnService, PurchaseReturn entity

Add list/search endpoints:
GET /purchase-returns — paginated list
GET /purchase-returns/search — search
POST /purchase-returns/{id}/complete
Supplier Payments — NEW in payment-service
api/SupplierPaymentController.java
application/SupplierPaymentService.java
api/dto/SupplierPaymentDto.java

Endpoint:
GET /api/v1/payments/supplier — list supplier payments
GET /api/v1/payments/supplier/{supplierId}/ledger
