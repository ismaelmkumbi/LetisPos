Phase Breakdown

Phase 1: Server Agent

Lightweight Go/Rust agent per Ubuntu server. Collects CPU, memory, disk, network. Exposes REST + pushes to Hub. Manages systemd/Docker services. Ships logs.

~2 weeks · Standalone value: Yes

Phase 2: Control Hub

Central API server. Aggregates agent data, stores metrics (TimescaleDB), manages auth/RBAC. WebSocket gateway for real-time dashboard updates.

~3 weeks · Depends on: Phase 1

Phase 3: Web Dashboard

React SPA. Service grid with real-time status. Metric charts (CPU/RAM). Log viewer. One-click restart/stop/deploy. Audit trail viewer.

~3 weeks · Depends on: Phase 2

Phase 4: Log Aggregator

Agent ships logs → Hub indexes (OpenSearch/Loki) → Dashboard shows searchable, filterable log streams with live tail.

~2 weeks · Depends on: Phase 2

Phase 5: Alerting Engine

Rule engine: CPU > 90%, service down, disk > 80%, API latency spike → Slack, email, webhook alerts. Incident creation and resolution tracking.

~2 weeks · Depends on: Phase 2

Phase 6: Deploy Pipeline

Connect GitHub → deploy to servers. Rollback with one click. Canary and blue/green deploys. Deployment history and diff viewer.

~3 weeks · Depends on: Phase 2

Phase 7: SSL & Domains

SSL certificate inventory. Expiry alerts. Auto-renew via Let's Encrypt. Domain/DNS management. HTTPS health checks.

~1 week · Depends on: Phase 2

Phases 1-3 = Minimum Viable Platform (8 weeks, single pane of glass with service control)
Phases 4-7 = Advanced Operations (add 8 weeks, full enterprise platform)
