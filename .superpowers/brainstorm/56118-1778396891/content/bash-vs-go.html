Why Go over Bash for the Agent?

Both can run on Ubuntu. The difference is what happens at 3 AM when a service is down.

Bash Agent

Problems at scale

  • No real HTTP server — need netcat hack or python -m http.server
  • Concurrent requests? Fork processes, race conditions on shared state
  • JSON parsing = jq dependency on every server
  • String escaping nightmares with log content
  • Signal handling in background loops is fragile
  • No type safety — runtime failures from unquoted variables
  • Docker API needs curl + parsing raw JSON by hand
  • Self-update means replacing running script = race conditions

Maintenance hell after 10 servers. Each new feature adds more edge cases.

Go Agent

Built for this

  • Production HTTP server in stdlib (net/http)
  • Goroutines handle concurrent requests trivially
  • encoding/json in stdlib — zero dependencies
  • Type safety catches bugs at compile time
  • Graceful shutdown with signal.Notify
  • Docker client library is mature and maintained
  • Single binary — scp to server, done
  • 10 MB, starts in milliseconds, uses ~8 MB RAM

Same binary runs on 1 server or 1000. Deploy with a one-line curl pipe bash.

Bash wins for: the install script, one-off admin tasks, simple cron jobs.
Go wins for: the agent daemon that runs 24/7 serving API requests.
