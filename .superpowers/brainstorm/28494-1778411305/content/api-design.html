API Design — document-service

REST endpoints that power the entire Document & Print system

Core Document Endpoints
POST /api/v1/documents/generate
Body: { documentType, referenceId, tenantId }
Returns: { documentId, pdfUrl, status }
Sync: generates PDF, stores in MinIO, returns immediately
GET /api/v1/documents/{id}
Returns: document metadata + presigned download URL
GET /api/v1/documents/{id}/pdf
Returns: PDF binary (inline) or 302 redirect to MinIO presigned URL
POST /api/v1/documents/{id}/email
Body: { to, subject, message }
Sends PDF as attachment via notification-service
POST /api/v1/documents/{id}/whatsapp
Body: { phone, message }
Sends PDF link via WhatsApp through notification-service
GET /api/v1/documents?type=quotation&referenceId=X&tenantId=Y
List/search documents with filters, pagination
Template Endpoints
GET /api/v1/templates
List available templates (code defaults + tenant overrides)
GET /api/v1/templates/{documentType}
Returns resolved template (override or default) + available placeholders
PUT /api/v1/templates/{documentType}
Body: { bodyHtml, name }
Creates or updates tenant template override. Validates placeholders.
DELETE /api/v1/templates/{documentType}
Removes tenant override, falls back to code default
POST /api/v1/templates/{documentType}/preview
Body: { bodyHtml, sampleData }
Generates preview PDF using sample/test data — for template editor
