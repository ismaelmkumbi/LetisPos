How should document preview work?

This determines the user experience in the frontend. Users need to see the document before printing or sending.

A

Live Browser Preview (React Components)

The same HTML/CSS templates are rendered as React components in the browser for instant preview. Gotenberg is only called for PDF generation (download/email/WhatsApp).

Pros

  • Instant preview (no server round-trip)
  • Same templates, same CSS = WYSIWYG
  • Works offline for POS receipts
  • No PDF rendering cost for preview
  • Matches existing Receipt.tsx pattern

Cons

  • Maintain template in two formats (React + HTML)
  • Risk of preview/PDF mismatch
  • Must sync template changes to both
B

Server-Side Preview (PDF → Image)

Backend generates PDF via Gotenberg, converts page 1 to PNG, returns image to frontend. Preview is always pixel-perfect with the final PDF. Already have pdfjs-dist for PDF→image.

Pros

  • 100% fidelity — preview IS the PDF
  • Single template source of truth
  • No duplicate template maintenance
  • Reuse pdfRender.ts already in codebase

Cons

  • ~1-2s delay for preview
  • Server load for every preview
  • No offline preview
  • Preview isn't interactive (image, not DOM)
C

Hybrid: React preview + PDF verify

React components for fast interactive preview during editing. One-click "Preview PDF" renders the real PDF via Gotenberg and shows it side-by-side or in a modal.

Pros

  • Fast editing experience
  • Final PDF verification available
  • Best of both worlds
  • Most POS/ERP systems use this pattern

Cons

  • Most engineering effort
  • Still have template in two forms
  • More code to maintain
