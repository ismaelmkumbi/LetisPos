How should document templates be managed?

This determines whether we need a visual template designer in Phase 1, or can defer it.

A

Code-Based Templates (Phase 1)

Templates live as Handlebars/Thymeleaf HTML files in the backend codebase. Developers create and maintain them. The template designer UI comes in Phase 2/3.

Pros

  • Fast to implement Phase 1
  • Type-safe, tested, versioned in git
  • No template DB schema needed yet
  • Full control over layout quality
  • Admins can't customize templates
  • Every change needs a developer
  • Template designer is deferred
B

Database-Driven Templates from Day 1

Templates stored in the database with a visual editor. Admins can drag-and-drop, edit placeholders, and preview changes in real-time. Same engine renders both.

Pros

  • Full self-service customization
  • Per-tenant branding
  • World-class competitive feature
  • No dev needed for template changes

Cons

  • 2-3x more Phase 1 effort
  • Template editor is a major UI project
  • DB schema + migration complexity
  • Harder to ensure consistent quality
C

Hybrid: Code defaults, DB overrides

Ship production-quality code-based templates as defaults. Allow tenants to upload custom CSS/HTML overrides per template type. Full visual editor comes later.

Pros

  • Great defaults out of the box
  • Customization possible without full editor
  • Incremental complexity
  • Matches Odoo's approach

Cons

  • Upload workflow is clunky vs visual editor
  • Still need override storage + merging logic
  • Preview becomes more complex
