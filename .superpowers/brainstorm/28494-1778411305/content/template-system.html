Template System Design

How templates are stored, resolved, and rendered into documents

Template Resolution Pipeline
1. Template Resolution (per tenant, per document type)
Check DB
Tenant override?
YES → use it
Fallback
Code default
Built-in Handlebars template
2. Data Assembly
document-service calls the relevant backend service via REST to fetch:
  • Company branding (logo, address, TIN, bank details)
  • Transaction data (sale, purchase, payment, etc.)
  • Related entities (customer, supplier, products, warehouse)
→ All data merged into a single TemplateContext map
3. HTML Rendering (Handlebars)
Template + TemplateContext → Handlebars.compile() → HTML string
CSS is embedded in <style> tags (no external stylesheets for print reliability)
QR codes rendered as inline SVG or base64 <img> via QRGen library
4. PDF Generation (Gotenberg)
POST HTML → Gotenberg /forms/chromium/convert/html
  • @page { size: A4; margin: 15mm; }
  • Watermarks applied via CSS (DRAFT, PAID, CANCELLED)
  • Page numbering via CSS @page counters
→ PDF byte[] returned in ~1-2s
5. Storage & Delivery
• PDF stored in MinIO (documents/{tenant}/{type}/{id}.pdf)
• Document metadata saved to documents table
• Presigned URL returned to frontend for download/view
• Email/WhatsApp delivery triggered via notification-service

  ├─ credit-note.hbs         <-- Credit note
  ├─ delivery-note.hbs      <-- Delivery note / packing slip

  ├─ customer-statement.hbs  <-- Customer statement

  └─ thermal-receipt.hbs     <-- 58/80mm thermal receipt

Each .hbs file = self-contained HTML with inline CSS, Handlebars placeholders
